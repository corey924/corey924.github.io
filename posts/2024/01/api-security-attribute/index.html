最小 API Key 驗證 Attribute 範例

2024-01-142 分鐘閱讀 技術Back-EndC#

以 ASP.NET Core Action Filter 實作最小 API Key 與來源 IP 檢查，並說明適用範圍與限制。

目錄

範例使用後端 .NET 8 與 C#。它示範如何用 ActionFilterAttribute 實作最小的 API Key 驗證，並用來源 IP 當作額外限制。

⚠️ 這不是完整的 API 安全方案。正式服務仍應使用 HTTPS、妥善保存密鑰、限制請求速率、記錄稽核事件，並依整合情境評估 OAuth、mTLS 或 API Gateway。來源 IP 白名單只能作為輔助條件，不能取代身分驗證。

適用範圍

這個範例適合受控的第三方整合，例如已知固定出口 IP 的內部服務。它不處理 CIDR 網段、密鑰輪替、撤銷機制或權限範圍；需要這些功能時，應交由 API Gateway、身分提供者或專門的驗證服務處理。

不要用 Request Host、X-Forwarded-Host 或字串包含比對來判定呼叫端網域。它們描述的是被呼叫服務的 Host，且轉送標頭只有在已設定可信任 Proxy 時才能使用。

設定服務名稱、密鑰與來源 IP

密鑰不應提交到版控。以下是結構範例；實際 ApiKey 應透過 User Secrets、環境變數或 Key Vault 等秘密儲存機制提供。

1"ExternalServices": {
2  "Sample": {
3    "ApiKey": "由秘密儲存機制提供",
4    "AllowedClientIPs": [
5      "203.0.113.10",
6      "2001:db8::10"
7    ]
8  }
9}

建立 Attribute

在 Web API 專案建立 /Filters/ApiSecurityAttribute.cs。範例只比對已解析的 IP，不做不可靠的網域反查或 Host 比對。以下程式假設已啟用 ASP.NET Core Web SDK 預設的 implicit usings；若專案關閉此設定，需自行補上 Microsoft.AspNetCore.Http、Microsoft.Extensions.Configuration 與其他使用到的命名空間。

 1using System.Net;
 2using System.Security.Cryptography;
 3using System.Text;
 4using Microsoft.AspNetCore.Mvc;
 5using Microsoft.AspNetCore.Mvc.Filters;
 6
 7public sealed class ApiSecurityAttribute : ActionFilterAttribute
 8{
 9  public string ServiceName { get; set; } = string.Empty;
10
11  public override async Task OnActionExecutionAsync(
12    ActionExecutingContext context,
13    ActionExecutionDelegate next)
14  {
15    var configuration = context.HttpContext.RequestServices
16      .GetRequiredService<IConfiguration>();
17    var serviceConfig = configuration.GetSection($"ExternalServices:{ServiceName}");
18
19    var configuredApiKey = serviceConfig["ApiKey"];
20    var requestApiKey = context.HttpContext.Request.Headers["X-API-KEY"].FirstOrDefault();
21    if (string.IsNullOrWhiteSpace(configuredApiKey)
22      || string.IsNullOrWhiteSpace(requestApiKey)
23      || !IsApiKeyMatch(requestApiKey, configuredApiKey))
24    {
25      context.Result = new UnauthorizedResult();
26      return;
27    }
28
29    var remoteIp = context.HttpContext.Connection.RemoteIpAddress;
30    var allowedClientIps = serviceConfig
31      .GetSection("AllowedClientIPs")
32      .Get<string[]>();
33
34    var isAllowedIp = remoteIp is not null
35      && allowedClientIps is not null
36      && allowedClientIps.Any(allowed =>
37        IPAddress.TryParse(allowed, out var allowedIp)
38        && allowedIp.Equals(remoteIp));
39
40    if (!isAllowedIp)
41    {
42      context.Result = new StatusCodeResult(StatusCodes.Status403Forbidden);
43      return;
44    }
45
46    await next();
47  }
48
49  private static bool IsApiKeyMatch(string requestApiKey, string configuredApiKey)
50  {
51    var requestBytes = Encoding.UTF8.GetBytes(requestApiKey);
52    var configuredBytes = Encoding.UTF8.GetBytes(configuredApiKey);
53
54    return requestBytes.Length == configuredBytes.Length
55      && CryptographicOperations.FixedTimeEquals(requestBytes, configuredBytes);
56  }
57}

若服務位於反向 Proxy 後方，RemoteIpAddress 可能是 Proxy 的 IP。此時應先依部署拓樸設定 ForwardedHeadersOptions.KnownProxies 或 KnownNetworks，只信任已知 Proxy 轉送的來源資訊；不要在 Filter 內直接讀取未驗證的 X-Forwarded-* 標頭。

套用到 Controller

1/// <summary>
2/// API 驗證測試。
3/// </summary>
4[HttpPost("test")]
5[ApiSecurity(ServiceName = "Sample")]
6public IActionResult Test()
7{
8  return Ok();
9}
